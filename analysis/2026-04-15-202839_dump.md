### Finding 3 — OPTIONS Preflight gap
- OPTIONS preflight to `app-us.smtp2go.com` with Origin: evil.com returns `ACAO: http://insights.hotjar.com` (static)
- No `Access-Control-Allow-Methods` header in OPTIONS response
- Preflighted cross-origin requests from ANY origin (incl. insights.hotjar.com) would fail due to missing ACAM

## What Failed / Dead Ends
- Origin reflection NOT present — server does not mirror back arbitrary origins
- All bypass probes (suffix, prefix, null) return same static `http://insights.hotjar.com` — no dynamic behavior
- No origin-keyed routing found

## Current Hypothesis
The server has a misconfigured static CORS policy that permanently whitelists `http://insights.hotjar.com` (a third-party analytics subdomain) with `ACAC: true` on all sensitive authenticated API endpoints. 

Exploitation requires one of:
1. XSS on `insights.hotjar.com` (feasible — it's a third-party with attack surface)
2. Subdomain takeover of `insights.hotjar.com`
3. HTTP downgrade — the ACAO is `http://` not `https://`, so a MITM of plaintext HTTP traffic to Hotjar could serve malicious JS

Severity: **Medium-High** (exploitable with prerequisites, not a direct arbitrary-origin reflection)

Note: `http://` vs `https://` — most modern browsers treat http and https origins as distinct, so this ACAO is for HTTP Hotjar, not HTTPS. This slightly reduces severity.
