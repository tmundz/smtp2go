## What I Found

### Critical: Server-rendered JS injection via userFullName
**Every authenticated page** (19 pages confirmed) contains this inline script block:
```javascript
zE(function(){
    var userIdentifier = '1010395';
    var userFullName = 'roy kent';;   // ← server-rendered, single-quoted
    var userMail = '0xcaphe+roy@wearehackerone.com';
    zE('webWidget', 'prefill', { name: { value: userFullName, ...
```

- Value is single-quoted and injected raw into `<script>` block
- No visible JS escaping in any of the 19 captured pages
- Double-semicolon (`'roy kent';;`) is a template artifact suggesting string interpolation
- Payload `'; alert(document.domain); //` would produce: `var userFullName = ''; alert(document.domain); //';;`

## Current Hypothesis
The **highest-value untested finding** is the inline JS injection via `userFullName`. If the server doesn't JS-encode the fullname on output, this is a **self-XSS** that becomes a proper stored XSS chained with:
1. IDOR-001 (LOGIN_AS another subaccount) → change their fullname → XSS fires on their every page load
2. Admin-editing team member fullname — any account with "owner" or "admin" role can update other members' fullnames via `update_member`, and those members get XSS on every page load

The self-XSS angle alone is low severity but the chain with IDOR or admin→victim escalation makes it reportable as **High**.
