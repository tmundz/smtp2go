## SSTI — FULLY DEAD ❌

Engine is **Handlebars/pybars**, NOT Jinja2.

Proof: `html_body=RESULT:{{7*7}}:END` → `"Parse error on line 1: Lexer error Token: Error{\"Unexpected character in expression: '*'\"}`

Handlebars uses `{{ var }}` syntax but doesn't allow arithmetic. The `{{ first_name }}` we saw is just variable substitution. Context is ONLY the `template_variables` dict passed in — no Flask config, request object, or server internals accessible.

The Jinja2 hypothesis was wrong because both Jinja2 AND Handlebars use `{{ }}` syntax. The `{{ first_name }}` in templates misled initial analysis.

## SSRF Registrar — DNS NS LOOKUP ONLY ❌

`action=registrar` does DNS NS record lookup, not HTTP:
- `google.com` → `{"registrar":"ns1.google.com"}` (actual NS record)
- `localhost` → `{"registrar":"Unknown"}` (no NS record)
- `169.254.169.254` → `{"registrar":"Unknown"}` (IP, no NS record)

NOT full-read SSRF. The server makes DNS queries for user-controlled domains but the protocol is DNS, not HTTP. Cannot access cloud metadata or internal services this way.
