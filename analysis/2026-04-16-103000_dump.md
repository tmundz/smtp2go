## Key Findings From Docs

### No URL filtering mentioned = significant signal
The docs explicitly document:
- HTTP as a valid protocol (no HTTPS-only restriction)
- USER:PASSWORD@HOST URL format (which is also a classic SSRF bypass vector)
- Zero mention of private IP blocking, URL allowlists, or RFC1918 restrictions

A production SaaS that blocks private IPs server-side would typically document this
behaviour (it causes user-facing errors and generates support tickets). The absence is
meaningful. Most likely they have no application-layer URL filter at all.

### Two different servers = two SSRF surfaces with different internal networks
- Surface A: Dashboard test button → fetch from app-us.smtp2go.com (143.42.179.218, NJ)
- Surface B: API /v3/webhook/add → fetch from api.smtp2go.com (172.233.132.16, LA)

These are different Linode instances. Different localhost = different internal services.
A port that's closed on the NJ instance may be open on LA, or vice versa.

### 10-second timeout is documented
Connection attempts to filtered ports will time out at exactly 10 seconds.
Connection refused (port closed) is faster (~immediate).
This lets you distinguish "blocked at firewall" vs "port closed" from timing alone.

### Interactsh source IP will be the app server IP
When you click Test Webhook on the dashboard, the fetch comes FROM app-us.smtp2go.com
(143.42.179.218). This is what you'll see in interactsh.
NOT from webhooks.smtp2go.com (that's production delivery only).

## URL Format Bypass Vectors (from docs)

The documented `USER:PASSWORD@HOST` format gives us:
```
http://user@127.0.0.1/          # If blocklist checks URL string not parsed host
http://127.0.0.1@legit.com/     # Reversed — parsed host = legit.com (not useful)
```
Python urllib.parse: `urlparse('http://user@127.0.0.1/').hostname` → '127.0.0.1'
So if they use urlparse().hostname for validation, the bypass doesn't work.
But if they do a string contains check ("127.0.0.1" in url), the `user@` prefix doesn't help either.
Most useful bypass is still decimal IP encoding: `http://2130706433/`
