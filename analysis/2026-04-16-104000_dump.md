## Attack Scenario (Plain English)

The goal is NOT just getting smtp2go to ping interactsh.
The interactsh step is just the proof that the server is making the fetch.

The real attack chain:
```
1. Create webhook with url=http://127.0.0.1:6379/
2. Click Test Webhook
3. smtp2go server (143.42.179.218) fetches its own Redis at localhost:6379
4. Redis responds with a banner/error
5. That response appears in the test results UI (el.response.substr(0,500))
6. You read Redis internals from your browser
7. Redis may contain: session tokens, cached API keys, Celery job payloads
8. Session token from Redis → authenticate as any user → account takeover
```

CVSS 7.7 High minimum if any internal service responds.
