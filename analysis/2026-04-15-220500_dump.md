## What I Found

### XSS-006 — Closed, NOT exploitable

Live HTTP response with payload fullname `'; alert(document.domain); //` showed:

**In HTML context** (nav bar):
```html
<span class="account-name">&#39;; alert(document.domain); //</span>
```

**In script context** (inline `<script>` block, the attack surface):
```javascript
var userFullName = '&#39;; alert(document.domain); //';;
```

The server encodes `'` → `&#39;` everywhere, including inside `<script>` blocks.
In raw-text `<script>` content, HTML entities are NOT decoded by the HTML parser.
The JS engine sees literal `&#39;` (5 chars) inside the string — no quote escape.
`alert()` never executes. Payload is fully contained within the string value.

**Root mitigation**: Django's template `|escape` filter (or AutoEscape) applies
HTML entity encoding to all string interpolation regardless of rendering context.
This is technically correct for HTML output. It happens to also prevent JS string
escape because the resulting `&#39;` is inert in raw-text script context.
