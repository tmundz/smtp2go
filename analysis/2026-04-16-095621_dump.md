### 🔴 SSRF — Likelihood: HIGH (7/10)

smtp2go makes outbound HTTP requests by design. This is the richest surface.

**Highest-signal areas:**

| Surface | JS Source | Request |
|---------|-----------|---------|
| Webhook URL config | `settings/webhooks/(index).3.inline.js:34` + `webhooks.tag` `removePopupRemove` | `POST /api/settings/webhooks/` body: `{url: "...", events: [...]}` |

**Why high**: The webhook "Test" button is an explicit server-side HTTP fetch. No filtering
has been observed in the JS. Blind SSRF via interactsh is the first test; cloud metadata
is the escalation. The `fileurl` attachment parameter in the outbound API is a separate
surface entirely — the server fetches the attachment from a URL you supply.

**Next action**: Create a webhook → set URL to interactsh endpoint → click Test.

### 🟡 SSTI — Likelihood: MEDIUM (5/10)

**Important correction from recon**: The template editor uses **Mustache.js client-side only**
for live preview. The server-side rendering engine is Python/Django (Gunicorn confirmed from
response headers). Email templates stored in `/api/settings/templates/` are rendered
server-side on delivery.

**Highest-signal areas:**

| Surface | JS Source | Request | Probe |
|---------|-----------|---------|-------|
| Email template body | `email-templates/main.js` save action | `POST /api/settings/templates/?action=save` body: `{template_body: "{{7*7}}"}` | `{{7*7}}` in delivered email = Jinja2 SSTI |
| Email template subject | Same as above | Same endpoint | `${7*7}` — if Mako or Tornado |
| Webhook `feedback_text` / `feedback_html` | `api-auth/main.js:1205,1206` | `update-active-user` body fields | Rendered server-side? Unknown |

**Probe sequence** (put in template body, trigger a test send):
```
{{7*7}}          → Jinja2 / Twig
${7*7}           → Mako / Freemarker  
<%= 7*7 %>       → ERB / EJS
#{7*7}           → Ruby ERB
*{7*7}           → Thymeleaf
```

If `49` appears in the delivered email → confirmed SSTI.

**Why medium not high**: Django template language uses `{{ var }}` syntax but is NOT
a full eval engine — `{{7*7}}` renders `49` in Jinja2 but is rejected by Django's
engine (DTL does not support expressions). However, if they're using Jinja2 as Django's
template backend (common in production stacks), this is live.

| `getRedirectUrl` server trust | `layout_subaccounts_dropdown.js` | `POST /api/login/` response | Open redirect / XSS via `javascript:` in goto |

**`update-active-user` is the clearest $500+ candidate**: if a subaccount session can
call this with any `full_api_key`, it's privilege escalation enabling:
- `blocked: true` → DoS (disable master's API key)
- `endpoints: [...]` → grant or restrict master key's API permissions
- `sandbox_mode: true` → silently disable all outbound email delivery
