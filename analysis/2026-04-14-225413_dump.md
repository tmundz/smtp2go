- This cookie name does NOT appear in any of the 238 JS files — it's a third-party cookie

### `login_id` AS SECONDARY AUTH PARAMETER
- `login_id` is a Flask itsdangerous signed/encrypted cookie
- Set by server on login, cleared on logout
- Also returned in `/end-points/` response body JSON as `login_id` field
- In `dashboard_main.js:227-228`: if cookie exists, sent as GET param to `/api/dashboard/main/`
- In the captured traffic, `login_id` is in the cookie jar but NOT being passed to API calls (cookie was non-null but the JS code path wasn't reached in these captures)
- Inner content: 188 bytes binary — likely Fernet/AES encrypted or an HMAC signature
- **Risk**: If server-side `/api/dashboard/main/` authenticates based on `login_id` parameter rather than session cookie, obtaining/forging it could be account takeover. Low confidence this is the case — likely defense-in-depth secondary check.
